# VS Code Agent Bridge 0.5.0

Status: unpublished Windows x64 side-load candidate. Marketplace publishing remains disabled.

## Scope

`0.5.0` changes the default workflow from mandatory checkpoint review or managed worktree isolation to capability-limited IDE autonomy on an ordinary experiment branch.

- Protocol v4 exposes exactly 21 bounded IDE tools.
- `autonomous` is the default: guarded edits, rename, formatting, pure-text Code Actions and saves can proceed without per-tool Codex approval.
- `review` restores write approval and explicit accepted-checkpoint Finalize semantics.
- `readOnly` removes Agent write tools from the managed Codex block and extension handlers independently reject writes.
- Terminal observation can expose metadata, Shell Integration execution state and sanitized captured output, but never creates a terminal, sends input or executes a command.
- Ordinary experiment branches plus user-controlled Git squash are the default. Automatic checkpoints remain outside Git.
- Managed Worktree remains available as an advanced, user-controlled isolation and one-commit promotion mode.

## Safety and privacy invariants

- Every Agent write requires a trusted local workspace, active experiment, explicit instance/session IDs and fresh document version plus SHA-256.
- Save only targets an open, existing in-scope `file:` document. It captures the final text after format/code-actions-on-save and never pretends multiple saves are atomic.
- Formatting invokes only `vscode.executeFormatDocumentProvider`; Code Actions containing commands or resource operations are inapplicable.
- Terminal output capture begins immediately on the Shell Integration start event. Older commands and missing prefixes are reported as incomplete.
- Captured output is sanitized and held only in memory: 1 MiB per execution, 16 MiB per window, completed-output-first eviction and 15-minute closed-terminal retention.
- Untrusted workspaces and `metadataOnly` expose terminal metadata only. `deny` rejects all terminal tools and clears retained sensitive execution state.
- Doctor reports policy, counts, coverage and memory totals only; it never prints command lines, output, source, tokens, IPC endpoints or absolute paths.
- Formal commits, sync, push and dangerous cleanup remain user operations. No Git or terminal write operation is Agent-callable.

## Verified in the development environment

- WebStorm project build and error-level inspections pass.
- `bun run check` passes protocol, RPC, MCP STDIO, configuration, storage, terminal-buffer and managed Git tests.
- Real Extension Host E2E verifies unsaved buffers, language services, guarded edit/rename, format and format-on-save, pure-text Code Actions, save checkpoints, autonomous/review/read-only transitions, real PowerShell Shell Integration output paging and terminal policy degradation.
- The same E2E run regresses the v0.4 two-window flow: ten private commits, target drift, explicit sync and one verified target commit with accepted-tree identity.
- Windows baseline EXE, platform VSIX, MCP initialize/list-tools, archive audit, SHA-256 files, isolated-profile VSIX E2E and the v0.5 test bundle are release gates.

## Known boundaries

- Windows x64 local VS Code desktop only; Remote SSH, WSL, Dev Containers, Codespaces, Linux, macOS and Windows ARM64 remain unsupported.
- Agent document tools do not create, delete or rename files and do not accept arbitrary command IDs.
- Terminal output before extension activation cannot be recovered. Shells without integration provide metadata but not command/output history.
- Sanitization and bounded capture reduce accidental disclosure but do not classify secrets. Choose `metadataOnly` or `deny` for sensitive terminals.
- Autonomous Finalize still requires all captured documents to be saved. If an accepted checkpoint exists, current content must match it.
- Managed Worktree requirements and v0.4 Git recovery boundaries are unchanged.
- Existing v0.4 experiment storage and installed MCP executable remain in place; switching Codex to v0.5 requires rerunning **Configure Codex**.
