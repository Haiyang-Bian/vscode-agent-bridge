# VS Code Agent Bridge 0.6.0

Status: unpublished Windows x64 side-load candidate. Marketplace publishing remains disabled.

## Scope

`0.6.0` upgrades the authenticated bridge to protocol v5 and exposes exactly 26 bounded IDE tools. It can be installed directly over `0.5.1`; it neither migrates nor deletes earlier experiment data or installed MCP executables. Users must rerun **Configure Codex** and restart Codex before clients use protocol v5.

The release adds three related capabilities:

- read-only inventory of trust, remote status and the presence of `.vscode`, `settings.json`, `launch.json`, `tasks.json` and `.code-workspace` configuration;
- user-confirmed, per-workspace-root experiment onboarding plus Agent tools to list, start, rename and checkpoint ordinary experiments;
- a native, memory-only Agent Activity view and configurable fixed-tab reveal before guarded text mutation.

Only `vscodeAgentBridge.experiments.enabled` and `vscodeAgentBridge.agentEditVisibility` are written during onboarding, through the VS Code Configuration API. Existing JSONC content is preserved. Launch, task and workspace files are never modified. The Agent cannot accept, restore, Finalize, abandon, pin or delete a session and cannot manage a Managed Worktree.

Activity is capped at 200 entries per extension lifetime. It records bounded titles, reasons, relative target names, counts, checkpoint IDs and stable result/error states. It does not persist source, replacement text, hashes, terminal command/output, credentials or absolute paths.

## Compatibility and safety

- Local, trusted Windows x64 VS Code desktop workspaces only for onboarding and writes.
- Untrusted, remote and virtual workspaces retain bounded reads but reject configuration and experiment writes.
- `autonomous`, `review` and `readOnly` remain enforced by both Codex configuration and extension handlers.
- Explicit `experiments.enabled=false` blocks every Agent write for that root without ending or deleting existing sessions.
- Document mutation retains active-session, explicit routing, version/hash, scope, size and one-use preconditions.
- No generic `executeCommand`, file-system, terminal-input, shell or Git MCP tool was added.
- Managed Worktree remains an advanced, user-only workflow and retains the v0.4 promotion invariants.
