# VS Code Agent Bridge 0.3.0

Status: unpublished Windows x64 side-load candidate. Marketplace publishing remains disabled.

## Scope

`0.3.0` adds recoverable Agent experiment sessions to the v0.2 local IDE bridge. It does not add managed Git worktrees or automatic delivery commits; those are reserved for v0.4.

- Protocol v3 with document SHA-256 and capture timestamps.
- Content-addressed, gzip-compressed local text snapshots, immutable events, leases, retention and recovery.
- Native Experiments tree, snapshot diffs, evidence, accepted candidates, restore and Finalize.
- Expiring, one-use multi-document Change Sets with version/hash preconditions and atomic application.
- Text-only rename through fixed VS Code provider commands; resource operations are rejected.
- Fourteen bounded MCP tools with write approval for apply/evidence operations.
- No automatic save, stage, commit, sync, push or experiment upload.

## Verified in the development environment

- `bun run check`: protocol, RPC, MCP STDIO, configuration, storage and Git-baseline tests pass.
- Real VS Code Extension Host E2E: unsaved buffers, diagnostics, symbols, definition, references, hover, experiment baseline, atomic stale rejection, rename, evidence, restore and Finalize pass.
- The E2E fixture is an isolated temporary Git repository and confirms v0.3 does not change Git HEAD.
- WebStorm project build and error-level inspections pass.
- Windows baseline EXE, platform VSIX, artifact smoke test, archive audit, SHA-256 files and test bundle are release gates.

## Known boundaries

- Local trusted Windows x64 workspaces only for experiments and Change Sets.
- Read-only v0.2 tools remain available in untrusted workspaces.
- No Remote SSH, WSL, Dev Containers, Codespaces, non-Windows or ARM64 support.
- v0.3 observes resource creation/deletion/rename but refuses whole-session restore when resource-level coverage is incomplete.
- Client-reported tests/builds are labelled `client-reported`; only diagnostics gathered by the extension are labelled automatic.
- Experiment snapshots may contain source code and stay in VS Code local extension storage.
