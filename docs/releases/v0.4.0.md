# VS Code Agent Bridge 0.4.0

Status: unpublished Windows x64 side-load candidate. Marketplace publishing remains disabled.

## Scope

`0.4.0` builds on the recoverable v0.3 experiment timeline with isolated, user-managed Git worktrees and one-commit promotion.

- A user command creates and locks a private worktree beneath `%LOCALAPPDATA%\VSCodeAgentBridge\worktrees` and opens it in a new VS Code window.
- Experiment checkpoints continue across the original and managed-worktree windows through the existing lease and recovery model.
- Users may create any number of private checkpoint commits; no Git write operation is exposed through MCP.
- Only a reachable, user-accepted commit from the private branch can be promoted.
- A moved target branch blocks Finalize. Synchronization is a separate user-confirmed rebase flow with explicit continue and abort commands.
- Finalize creates a commit object from the accepted tree and cherry-picks it onto the clean target, then verifies its parent and tree.
- Successful promotion adds exactly one commit to the target branch. It never pushes and never automatically deletes the private branch or worktree.
- Cleanup validates the registered worktree and managed root. Force removal requires a separate destructive confirmation.

The MCP surface remains the fourteen protocol-v3 IDE tools introduced in v0.3. There is no Agent-callable Git, shell, terminal, filesystem or generic VS Code command tool.

## Verified in the development environment

- `bun run check`: protocol, RPC, MCP STDIO, configuration, experiment storage and managed Git tests pass.
- Managed Git tests cover locked worktrees, ten private commits to one target commit, accepted-tree identity, detached/bare/submodule/merge boundaries, target drift, rebase conflict abort, moved refs and exact cleanup guards.
- A real two-window VS Code Extension Host E2E creates a managed worktree, makes ten private commits, rejects a moved target, synchronizes explicitly, and verifies that promotion adds one target commit whose tree matches the accepted candidate.
- WebStorm project build and error-level inspections pass.
- Windows baseline EXE, platform VSIX, artifact smoke test, archive audit, SHA-256 files and the v0.4 test bundle are release gates.

## Known boundaries

- Managed worktrees require a local trusted Windows x64 workspace, a named local branch, Git, a completely clean target and no unsaved target documents.
- Bare repositories, detached HEAD, submodule superprojects, virtual/remote workspaces and in-progress merge/rebase/cherry-pick/bisect operations are rejected.
- v0.4 does not fetch, pull, push, modify remotes/configuration, prune worktrees or delete them due to age or storage limits.
- Private commits use the user's Git identity, hooks and signing configuration. Hooks may have effects outside the repository that the extension cannot roll back.
- Automatic synchronization is intentionally absent. Rewritten or backwards target history, or private merge history that requires automatic rebase, must be handled by starting a new session or by the user outside the bridge.
- A failed cherry-pick is aborted when possible. If the target cannot be restored and verified, the session enters `promotion-recovery-required` and all further managed writes stop.
- v0.3 workspace-mode experiments remain available and still do not create formal commits.
