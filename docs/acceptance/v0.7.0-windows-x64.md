# VS Code Agent Bridge 0.7.0 Windows x64 acceptance

Run this procedure on a different Windows x64 computer with a clean VS Code profile, Git, no Bun or Node.js, and no clone of this repository. Use an unrelated disposable local Git repository. A language runtime and its normal VS Code debugger may be installed solely for the named Debug test.

## Install, upgrade and migration

1. Verify the extracted bundle and VSIX against `SHA256SUMS.txt`.
2. Install `0.6.1`, choose one restrictive legacy policy (`review`, `readOnly`, `metadataOnly` or `deny`), configure Codex once, then install `vscode-agent-bridge-0.7.0-win32-x64.vsix` directly over it. Do not uninstall first.
3. Confirm the extension ID is `AliceLin.vscode-agent-bridge`, version is `0.7.0`, and earlier experiment history remains readable.
4. Before migration, confirm Doctor says publication is paused and Codex cannot discover this window. Run **Configure Bridge**, choose enabled plus `explicit`, rerun **Configure Codex**, restart Codex and confirm protocol v6 with 42 tools.
5. Confirm Doctor and MCP results contain no token, IPC endpoint, source, Task command/output, Debug expression/value, DAP message, username or absolute path.

## Experiment, JSONC and resources

1. Start a new ordinary experiment in the disposable repository. Confirm it uses resource-history schema v2 and Git HEAD does not change.
2. Create `.vscode/settings.json` containing comments, trailing commas and an unrelated setting. Through the Bridge, read its hash and add/replace/remove a harmless setting. Confirm comments, formatting style and unrelated fields survive.
3. Attempt to modify `.code-workspace` `folders`, a remote authority and `.git/config`; each must be rejected without partial changes.
4. Prepare and apply creation of a UTF-8 text file and nested directory, rename the file, then delete it. Confirm stale hashes, path traversal, a symbolic link/junction and binary content are rejected atomically.
5. Create an accepted checkpoint containing the new resource structure, change/delete those resources, then run the user-only restore command. Confirm the exact text bytes and structure return on disk, restored buffers are saved, and a restore checkpoint appears.

## Tasks and terminal observation

1. While `executionMode=explicit`, use guarded JSONC updates to create one finite build/test Task and one identical Task with `runOptions.runOn: "folderOpen"`. Confirm the delayed Task update is rejected.
2. List Tasks, record the chosen Task ID/fingerprint, run it, observe queued/running/exited state, sanitized incremental terminal output and exit code, then confirm the task's expected workspace text output is captured by the experiment.
3. Change the Task definition and confirm the old fingerprint returns `TASK_CHANGED`. Start a long-running disposable Task and terminate it through `vscode_terminate_task`.
4. Switch to `aggressive`, add the folder-open setting and confirm `deferredEffects=true` plus Doctor/Activity warning. Remove it again before continuing.
5. Confirm there is still no terminal create/input/arbitrary-command MCP tool and raw command/output is absent from Activity and Doctor.

## Debug

1. Add a static named launch configuration for a debugger/runtime already installed on the test computer. List it and start it only by its returned name/fingerprint; an inline command object must be rejected.
2. Set a source breakpoint inside the experiment root, stop on it, and page through threads, stack frames, scopes and variables.
3. Exercise pause, continue, next, step in, step out and restart where the adapter supports them. Confirm a stale frame or variables reference is rejected after resume.
4. Evaluate a harmless expression and set one disposable variable. Confirm the expression and values never appear in Activity, Doctor, logs or experiment metadata.
5. Attempt an arbitrary DAP command and an out-of-root source breakpoint; both must be rejected. Terminate the session and confirm it appears as recently ended.

## Master switch, recovery limits and regression

1. Disable the master switch. Confirm the instance descriptor disappears, existing MCP connections close and no window is discoverable. Re-enable it and confirm discovery resumes with the same local UI data intact.
2. Run a Task or Debug action that changes only a disposable external marker, then restore the accepted workspace checkpoint. Confirm workspace resources restore but the external marker does not; the UI/report must not claim external rollback.
3. Recheck unsaved document reads, diagnostics, symbols, definitions, references, hover, format no-op, pure-text Code Action, editor visibility, terminal observation and Managed Worktree advanced-mode smoke behavior.
4. Confirm experiment checkpoints never add Git commits. Use normal Git squash to create the one formal commit only after review.

## Report

Produce privacy-scrubbed Markdown and JSON reports containing Windows, VS Code, extension/protocol versions, all artifact SHA-256 values, each section/result, coverage limitations and `overallStatus`. Replace machine-specific roots with placeholders. Do not include source, raw configuration, Task commands/output, Debug expressions/values, DAP messages, tokens, endpoints, emails or personal identifiers.

Only `overallStatus: passed` marks `0.7.0` as Windows x64 cross-machine verified. A failure keeps the existing candidate immutable and should produce a later patch rather than rewriting this version.
