# VS Code Agent Bridge 0.9.0 Windows x64 acceptance

Run this procedure on a different Windows x64 computer with a clean VS Code profile, no Bun or Node.js, and no clone of this repository. Install the checksum-verified VSIX directly over `0.8.0`; do not uninstall first.

- VSIX: `5e62043dd5afb4fdb48a952a0fbe541bd3046077a5a04b8b7c9a38ba5545e223`
- Test bundle: `e296e01033fc9de4da6a933292a8dc3ee3ab01c02ddc8510baaeb1b867da13ee`

## Upgrade and extension reflection

1. Confirm extension ID `AliceLin.vscode-agent-bridge`, version `0.9.0`, protocol v8 and exactly 53 tools after rerunning **Configure Codex** and restarting Codex.
2. Confirm Overview reports installed/active extension counts and IDE-signal counts without extension paths, source, output, tokens or private Profile data.
3. Call `vscode_list_extensions`, then inspect active and inactive entries with `vscode_get_extension_details`. Confirm neither listing nor details activates an inactive extension.
4. Confirm manifest-declared languages, debuggers, Tasks, commands, themes and configuration keys are metadata only; contributed commands cannot be executed through the Bridge.
5. Call `vscode_get_extension_configuration_schema` for the Bridge and one language extension. Confirm pagination and malformed-manifest isolation. Confirm `vscode_get_profile_context` returns unavailable stable fields as `null` without reading private Profile files.

## Problems, Output and Debug Console

1. Produce, change and remove diagnostics in an opened workspace file. Confirm `vscode_list_diagnostic_events` reports added/changed/removed summaries with cursor pagination and filters, but stores no diagnostic body.
2. Open the VS Code Output panel and explicitly select one extension channel with a unique marker. Confirm `vscode_list_output_sources` distinguishes metadata-only, visible and captured sources. Read the selected channel with `vscode_read_visible_output`.
3. Switch away or close that Output document. Confirm the Bridge returns `OUTPUT_NOT_VISIBLE` and never switches the panel back automatically. Confirm it does not expose arbitrary private log files or claim all extension channels are enumerable.
4. Start a named debug configuration that writes unique console/stdout/stderr markers. Confirm `vscode_list_debug_output` and `vscode_read_debug_output` return sanitized incremental pages, categories and workspace-relative source positions.
5. Emit a telemetry-category marker and an ANSI/control-sequence marker. Confirm telemetry is absent and controls are removed. Restart the extension and confirm pre-activation Debug Console history is not claimed.

## Regression and report

1. Recheck v0.8 Hub, local insights, experiments, formatting no-op, pure-text Code Action, Terminal, Tasks, Debug control, resource recovery and Managed Worktree promotion.
2. Confirm no generic command, arbitrary extension exports, Output-channel switcher, private Profile reader, terminal input, arbitrary DAP request, shell or unrestricted filesystem tool exists.
3. Produce privacy-scrubbed Markdown and JSON reports containing Windows, VS Code, extension/protocol versions, artifact SHA-256 values, per-tool results and explicit `metadataOnly`/`visible`/`captured`/`unavailable` coverage.

Only `overallStatus: passed` marks `0.9.0` as Windows x64 cross-machine verified. A failure keeps this candidate immutable and should produce a patch release.
