# VS Code Agent Bridge 0.6.1 Windows x64 acceptance

Run this procedure on a Windows x64 computer with a clean VS Code profile, Git, no Bun or Node.js, and an unrelated disposable local repository. `0.6.1` is an unpublished side-load patch candidate.

## Install and compatibility

1. Verify the test bundle and extracted artifacts against `SHA256SUMS.txt`.
2. Install `0.6.0`, create an ordinary experiment and at least one checkpoint, then install `vscode-agent-bridge-0.6.1-win32-x64.vsix` directly over it. Do not uninstall first.
3. Confirm the extension ID is `AliceLin.vscode-agent-bridge`, version is `0.6.1`, and the earlier experiment remains readable.
4. Rerun **Configure Codex**, restart Codex, and confirm Doctor reports protocol v5, 26 tools and aligned versions without source, tokens, IPC endpoints, terminal content or absolute paths.

## Cancellation and readiness

1. Reload the VS Code window while an experiment with substantial checkpoint history is active.
2. Poll instances immediately. The new instance must appear with `lifecycle=initializing` or `ready`; it must not disappear for the full recovery interval.
3. If initializing is observed, a state-dependent call must return `BRIDGE_INITIALIZING`. Record time to descriptor discovery and time to `ready`.
4. In a fresh root without `.vscode`, ask Codex to start an experiment and leave the native onboarding prompt unanswered for more than 10 seconds. Confirm the request remains pending and can still complete successfully within the bounded interactive timeout.
5. Repeat, but cancel the Codex request before answering. Wait at least 12 seconds. Confirm `.vscode` was not created, setup remains `unconfigured`, no experiment was created, and no delayed Activity success appears.

## Capture and v0.6 regression

1. In an active Git-backed experiment, add `ignored-output/` to `.gitignore`, create and modify files below it, and confirm no external-change checkpoint is added.
2. Open one ignored text file in VS Code, modify its buffer, and confirm open-document observation still creates the appropriate checkpoint.
3. Confirm ordinary tracked edits, manual saves, explicit checkpoints, format no-op, pure-text Code Action, editor visibility and terminal read-only observation still pass the `0.6.0` acceptance expectations.
4. Confirm no generic filesystem, terminal input/execution, command or Agent-callable Git tool exists.

## Report

Produce a privacy-scrubbed Markdown and JSON report containing versions and SHA-256 values, discovery and readiness timings, cancellation side effects, ignored/open-buffer capture results, regression results and `overallStatus`. Replace machine-specific roots and omit source, raw configuration, tokens, endpoints, terminal commands/output and personal identifiers. A failure keeps the candidate unpublished and must not rewrite the earlier audit.
