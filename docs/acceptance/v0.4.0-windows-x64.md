# VS Code Agent Bridge 0.4.0 Windows x64 acceptance

Use this procedure on a different Windows x64 computer with a clean VS Code profile, Git, no Bun or Node.js, and no clone of this repository. `0.4.0` is an unpublished side-load candidate.

## Install and configure

1. Verify the test-bundle archive against its `.sha256` file, then verify every extracted file against `SHA256SUMS.txt`.
2. Install `vscode-agent-bridge-0.4.0-win32-x64.vsix` using **Extensions > ... > Install from VSIX...**.
3. Confirm the extension ID is `AliceLin.vscode-agent-bridge` and version is `0.4.0`.
4. Run **VS Code Agent Bridge: Configure Codex**, confirm the operation, restart Codex, and run **Run Doctor**.
5. Doctor must report protocol v3, aligned versions, a live bridge, current config and healthy experiment storage without printing a username, source text, token, IPC endpoint or absolute path.

## Repository fixture

Create a new ordinary local Git repository containing two small TypeScript files and a `tsconfig.json`. Configure a local test identity if the computer has no Git identity, make an initial commit on a named branch, and confirm:

- the target worktree is completely clean;
- no document under the repository is unsaved;
- no merge, rebase, cherry-pick or bisect is active;
- the repository has no submodules.

Record the target branch, initial target HEAD and initial target tree.

## Managed experiment scenario

1. From the target window run **Start Managed Worktree Experiment**, enter a title, review the branch/base confirmation and approve creation.
2. Confirm a second VS Code window opens at a locked private worktree and that the experiment appears in the Agent Experiments view after the new window takes over its lease.
3. In the managed window, make a small saved edit and run **Create Private Checkpoint Commit** ten times, using a different message each time. The target window's branch and HEAD must remain unchanged throughout.
4. Confirm each private commit is represented in the experiment timeline. Select the tenth reachable Git checkpoint and run **Mark Checkpoint as Accepted**.
5. Create one more private commit after the accepted candidate. Keep the tenth commit accepted; this proves promotion uses the selected historical tree rather than the current private HEAD.
6. In the original target window, make an independent clean commit that does not conflict with the experiment. **Finalize Managed Experiment** must refuse with `TARGET_MOVED` and must not change either worktree.
7. Return to the managed window and run **Sync Managed Experiment**. Review the commit range and confirm the rebase. After success, verify the previous accepted candidate is cleared, then select the rebased commit representing the intended candidate again.
8. Confirm both target and managed worktrees are clean. From the original target window run **Finalize Managed Experiment**, review the full file list/stat/diff, enter a non-empty formal commit message, and confirm promotion.
9. Verify the target branch gained exactly one commit during Finalize. Its sole parent must be the post-drift target HEAD and its tree must equal the newly accepted private commit tree.
10. Confirm no fetch, pull, push or remote/configuration change occurred. Confirm the managed worktree and private branch still exist after Finalize.

## Failure and cleanup scenarios

Run these with disposable repositories or sessions; do not risk valuable work.

1. Start a second managed experiment, make the target dirty or leave an unsaved target document, and confirm Finalize refuses without modifying either repository.
2. Create a rebase conflict during **Sync Managed Experiment**. Confirm the session enters a conflicted state and only review, **Continue Experiment Sync** or **Abort Experiment Sync** is offered. Abort and verify the prior private history is restored.
3. Use a disposable failing commit hook during promotion. Confirm the extension attempts `cherry-pick --abort`; if recovery succeeds, the target must return to its prior clean HEAD. If it cannot be verified, record `promotion-recovery-required` and do not attempt further managed writes.
4. Finalize or abandon a disposable managed session, then run **Delete Managed Worktree**. Confirm the dialog shows the exact absolute target. Normal cleanup must refuse a dirty worktree; the separately confirmed force path may remove only that verified managed worktree.
5. Move the private ref before cleanup and confirm the extension retains the branch rather than deleting an unexpected ref. Run **Repair Managed Experiments** and confirm it reports missing/mismatched state without recursively deleting anything.

## Report

Produce `vscode-agent-bridge-0.4.0-acceptance.md` and matching JSON with:

- Windows architecture/version, Git version, VS Code version and extension version;
- VSIX and installed MCP executable SHA-256;
- initial target HEAD, accepted commit, pre-promotion target HEAD and final formal commit using abbreviated SHAs;
- one pass/fail item for installation, Doctor, worktree creation/lock, cross-window lease, ten private commits, historical candidate selection, target-drift refusal, explicit sync, one-commit promotion, accepted-tree identity, no remote operations, recovery behavior and exact cleanup;
- `targetCommitsAddedByFinalize: 1`;
- `acceptedTreeEqualsFinalTree: true`;
- `overallStatus: "passed" | "failed"`.

Replace home, repository and managed-worktree prefixes with `<HOME>`, `<REPOSITORY>` and `<MANAGED_WORKTREE>`. Do not include usernames, email addresses, tokens, IPC endpoints, full Codex configuration, raw absolute paths or unrelated source content. A failed item keeps this candidate unpublished and should result in a patch candidate.
