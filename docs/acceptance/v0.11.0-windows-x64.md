# VS Code Agent Bridge 0.11.0 Windows x64 acceptance

Run this procedure on a different Windows x64 computer with a clean VS Code Profile, no Bun or Node.js, and no clone of this repository. Install the checksum-verified VSIX directly over `0.10.0`; do not uninstall first. Verify all files against the supplied `SHA256SUMS.txt` before installation.

## Upgrade and catalog

1. Confirm extension ID `AliceLin.vscode-agent-bridge`, version `0.11.0`, protocol v10 and exactly 60 tools after rerunning **Configure Codex** and restarting Codex.
2. Confirm the v0.10 Hub, Marketplace, current-Profile, Problems, Output and Debug Console workflows still work.
3. Call `vscode_list_extension_integrations`. Confirm it returns only the reviewed `python.environment` integration, fixed extension ID `ms-python.python`, the supported version range and `activationPolicy: onStateRequest`.
4. Confirm listing the catalog does not activate an inactive Python extension.
5. Confirm the state tool is read-only but marked non-idempotent/open-world because the explicit request may activate reviewed extension code.

## Official Python environment integration

1. In a Profile without the Python extension, call `vscode_get_extension_integration_state` for the current local trusted root. Confirm `status: unavailable`, `reason: notInstalled`, `activatedByRequest: false` and no environment payload.
2. Use the v0.10 Marketplace tools to search for and install the official `ms-python.python` extension. Complete VS Code's native Publisher Trust/reload flow; do not install from an arbitrary URL or VSIX through MCP.
3. Open a Python project, select a known interpreter with the Python extension, then explicitly request `python.environment` state.
4. Confirm the result identifies whether this request activated Python and returns only interpreter path, environment type/name, Python version and bitness.
5. Confirm the result and Activity/Doctor/logs contain no environment variables, package list, credentials, Python output, activation exports or raw extension logs.
6. Disable or replace the extension with a version outside the documented supported range and confirm fail-closed `EXTENSION_VERSION_UNSUPPORTED`. Re-enable the supported version afterward.
7. Confirm no MCP input accepts an arbitrary extension ID, command ID, export method, JSON arguments, environment creation, package installation or generic extension action.

## Regression and report

1. Recheck experiments, formatting no-op, pure-text Code Action, resource recovery, Terminal, Tasks, bounded Debug, Marketplace/current-Profile orchestration and Managed Worktree promotion.
2. Confirm no generic command, arbitrary extension exports, shell, terminal input, unrestricted filesystem or Agent-callable Git tool exists.
3. Produce privacy-scrubbed Markdown and JSON reports with Windows/VS Code/extension/protocol versions, supplied artifact SHA-256 values, per-tool results, activation state and explicit complete/visible/captured/adapter/unavailable coverage.

Only `overallStatus: passed` marks `0.11.0` as Windows x64 cross-machine verified. A failure keeps this candidate immutable and should produce a patch release.
