# VS Code Agent Bridge 0.10.0 Windows x64 acceptance

Run this procedure on a different Windows x64 computer with a clean VS Code Profile, no Bun or Node.js, and no clone of this repository. Install the checksum-verified VSIX directly over `0.9.0`; do not uninstall first. Verify all files against the supplied `SHA256SUMS.txt` before installation.

## Upgrade and catalog

1. Confirm extension ID `AliceLin.vscode-agent-bridge`, version `0.10.0`, protocol v9 and exactly 58 tools after rerunning **Configure Codex** and restarting Codex.
2. Confirm the v0.9 Hub, Problems, Output and Debug Console coverage still works and no installed extension is activated merely by inspection.
3. Confirm the five new tool annotations identify search/get as reads, prepare as non-idempotent preparation, and install/configuration updates as writes with accurate open-world/recovery metadata.

## Marketplace search and installation

1. In an active ordinary experiment, search for the official Microsoft Python extension and one verified third-party result. Confirm `official` and `verifiedPublisher` are separate fields and the maintainer-directory version is present.
2. Confirm installed and workspace-recommended candidates rank ahead of ordinary third-party results without being mislabelled official.
3. Prepare the Microsoft Python install. Confirm the plan fixes ID, publisher, stable version, current Profile, TTL and a complete dependency/extension-pack graph of at most 20 members.
4. Apply the plan. Complete any native Publisher Trust prompt. Confirm the result is `installed`, `pendingUserTrust`, `pendingReload` or `userActionRequired` honestly; no trust prompt is bypassed and no false success is reported.
5. Apply the same plan again and confirm rejection. Prepare another plan, allow the Marketplace version/state to change or let it expire, and confirm fail-closed rejection.
6. Confirm URL, local VSIX, downgrade, uninstall, update, arbitrary command and CLI installation inputs do not exist on the MCP surface.

## Current Profile configuration

1. Read a non-sensitive declared setting from an installed extension at Global, Workspace and WorkspaceFolder scope where supported. Confirm canonical hashes and declared type/scope metadata.
2. Update one Global setting with the exact hash. Confirm the new value belongs to the current Profile and Activity contains no value. Run **Undo Last Agent Profile Change** and confirm restoration only while the current value still matches the journal.
3. Update a Workspace/Folder setting and confirm an experiment checkpoint is created. Change the value outside the Bridge and verify the stale hash is rejected.
4. Attempt an undeclared key, wrong type, unsupported scope and a name containing token/password/secret/credential/apiKey. Confirm `EXTENSION_CONFIGURATION_DENIED` without value leakage.
5. Run **Create Capability Profile**. Confirm it opens VS Code's native Profiles manager and does not silently create or switch a Profile. Open the chosen Profile in a new window and inventory it again.

## Regression and report

1. Recheck experiments, formatting no-op, pure-text Code Action, resource recovery, Terminal, Tasks, bounded Debug and Managed Worktree promotion.
2. Confirm no generic command, arbitrary extension exports, arbitrary Marketplace/web scraper, CLI/VSIX installer, private Profile reader, SecretStorage reader, terminal input, shell or unrestricted filesystem tool exists.
3. Produce privacy-scrubbed Markdown and JSON reports with Windows/VS Code/extension/protocol versions, supplied artifact SHA-256 values, per-tool results, Publisher Trust/reload state and explicit coverage.

Only `overallStatus: passed` marks `0.10.0` as Windows x64 cross-machine verified. A failure keeps this candidate immutable and should produce a patch release.
