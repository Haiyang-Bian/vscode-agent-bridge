# v0.13.0 Windows x64 acceptance

This is an unpublished HTTP-only candidate. Keep the v0.12 acceptance record unchanged. A passing local run does not establish a second-user ACL or different-machine result.

## Preconditions

Use Windows x64, local trusted VS Code and a fresh Codex client. Verify the supplied VSIX SHA-256 against the bundle manifest. No Bun, Node.js or source checkout is needed for installation. Preserve the prior Codex configuration and installed version files. Do not end existing client-owned processes by executable name.

## Procedure

1. Install the VSIX in the chosen VS Code Profile and run Configure Codex. Confirm the current-user login task and service installation. An existing unmarked bridge table must be reported as a conflict.
2. Run Doctor. Confirm version 0.13.0, RPC v11, 64 tools, current managed HTTP configuration, a healthy shared PID and a valid login task. The old 0.12.0 extension remains protocol-compatible with the new server.
3. From two fresh Codex clients, call `vscode_list_instances` and an explicit-instance editor/context read. Confirm the service PID is unchanged and tool discovery does not create another daemon.
4. Close all test VS Code windows. A fresh MCP client must still initialize/list tools; IDE-dependent reads return `NO_VSCODE_INSTANCE`. Start VS Code later and retry through the same daemon.
5. Reload a window; check its descriptor is republished and the daemon PID is unchanged. With two windows, implicit routing must return `AMBIGUOUS_INSTANCE`; explicit instance IDs remain usable.
6. Cancel a pending onboarding interaction in one client, then finish/dismiss the original interaction. Confirm no delayed settings or experiment writes occur, and the other client remains usable.
7. Inspect the login task: InteractiveToken, LeastPrivilege, IgnoreNew, no runtime limit, no network/idle/battery prerequisites, retry every minute up to three times. Run the task on demand. A deliberate sign-out/sign-in test may supplement this without interrupting unrelated work.
8. Exercise service stop/start/restart. Stop drains for at most ten seconds before cancellation and usage flush. Kill only a test-owned daemon to verify OS lock release and managed restart; never kill by process name.
9. Exercise install twice, upgrade, configuration conflict, failed-candidate rollback and uninstall in a separate `--service-dir`, registry, task and config. Only the candidate is stopped on rollback; previous task/configuration and files are preserved.
10. Inspect protected ACLs on identity, configuration, backups and transaction files. Independently attempt denied access from another Windows identity before marking the cross-identity security check passed.

## Evidence and recovery

Record version, commit, VSIX/EXE hashes, actual MCP tool names/outcomes, shared PID and legacy-process count separately. Do not copy credentials, IPC addresses, raw Codex configuration or source snapshots into reports. Follow [installation and recovery](../installation.md) for a retained transaction journal or concurrent configuration edits. Place executed results in a new dated report under `docs/audits`.
