# VS Code Agent Bridge 0.6.0 Windows x64 acceptance

Run this procedure on a second Windows x64 computer with a clean VS Code profile, Git, no Bun or Node.js, and no clone of this repository. Use an unrelated disposable local repository. `0.6.0` is an unpublished side-load candidate.

## Install and protocol upgrade

1. Verify the test-bundle archive against its `.sha256` file, then verify extracted files against `SHA256SUMS.txt`.
2. Install the `0.5.1` VSIX, configure it once, then install `vscode-agent-bridge-0.6.0-win32-x64.vsix` directly over it. Do not uninstall first.
3. Confirm the extension ID is `AliceLin.vscode-agent-bridge`, the installed version is `0.6.0`, and earlier experiment data remains visible.
4. Before reconfiguration, run **Run Doctor** and confirm it detects the stale `0.5.x` MCP/configuration. Run **Configure Agent Policies**, select `autonomous + allow`, rerun **Configure Codex**, and restart Codex.
5. Confirm Doctor now reports protocol v5, 26 tools, aligned versions, live bridge, current policies and healthy storage. It must not print source, terminal command/output, tokens, IPC endpoints, usernames or absolute paths.

## First-use workspace onboarding

Create and commit an unrelated local TypeScript project with two existing source files and a named experiment branch. Do not create `.vscode`. Open the folder in VS Code.

1. Ask Codex to call `vscode_get_workspace_setup`. It must report a trusted local root, `onboarding=unconfigured`, missing `.vscode`, settings, launch and tasks, and no configuration contents.
2. Ask Codex to start an ordinary experiment with a short name derived from the task. The modal prompt must show the proposed title.
3. Choose **Review Setup**, confirm only presence/state is shown, return to the prompt, and choose **Not Now**. Verify no file changed and repeated Agent requests in this window are declined without repeated prompts.
4. Run the user command **Configure Workspace Experiment** and enable `focusFirst`, or repeat the Agent request and choose **Create Experiment**.
5. Verify `.vscode/settings.json` was created with only the two Bridge settings. Existing files, `launch.json`, `tasks.json` and any `.code-workspace` file must remain absent or byte-identical.
6. In a separate disposable root with a commented JSONC settings file, enable experiments and verify comments plus unrelated keys remain intact.
7. Explicitly disable experiments. Confirm an Agent start/write returns `POLICY_DENIED` without ending or deleting an existing experiment. Re-enable for the remaining tests.

## Experiment reflection and visible writes

1. Ask Codex to list experiments for the selected root. Confirm ordinary and Managed metadata can be read but no snapshot source is returned.
2. Ask Codex to start an ordinary experiment named for the task, rename it using the current title, and create an explicit checkpoint. Confirm the native Experiments view updates.
3. Retry rename with the stale prior title. It must return `EXPERIMENT_STATE_CHANGED` without overwriting the current title.
4. Confirm Codex has no tool to accept, restore, Finalize, abandon, pin, delete or modify a Managed session.
5. Ask Codex to apply one guarded Change Set to two existing files. Before text changes, both must open as fixed tabs and the first requested file must receive focus.
6. Watch **Agent Activity** and the status bar during start, rename, checkpoint, apply, format, save and Code Action operations. Confirm queued/running and final states appear; a zero-edit format ends as `no-op`.
7. Confirm Activity contains only relative/basename targets, bounded rationale, counts, checkpoint IDs and stable error codes. It must contain no source, replacement text, hashes, terminal content, tokens or absolute paths. Restart VS Code and confirm Activity is empty while experiment checkpoints remain.
8. Repeat a harmless guarded edit under `focusEach`, `firstOnly` and `off`. Confirm each visibility policy. Closing a tab after the mutation must not cause it to reopen at operation completion.

## v0.5 capability regression

1. Read an unsaved unique TypeScript marker and confirm it is absent from the disk file.
2. Apply guarded multi-document edits; make one target stale and confirm the whole Change Set is rejected without partial modification.
3. Format a document with a real provider, then format the already formatted result. The second call must succeed with `applied=false`, `editCount=0`, `checkpointId=null` and unchanged version/hash, without opening a new tab.
4. Temporarily enable `vscodeAgentBridge.enableAcceptanceFixtures`; apply the command-free pure-text acceptance Quick Fix to an existing `*.bridgeaction` file containing `BROKEN_E2E`, verify `FIXED_E2E`, then disable the fixture. Command/resource actions must remain inapplicable.
5. Save an existing document and confirm format-on-save final text/hash and a `save` checkpoint. Untitled, out-of-root and stale saves must be rejected.
6. Manually run a terminal command that prints a marker, waits and exits. Ask Codex for incremental status, sanitized paged output and exit code. Confirm no terminal create/input/execute MCP tool exists.
7. Switch to `review`; rerun **Configure Codex** and confirm Agent writes require approval. Switch to `readOnly + metadataOnly`; confirm every Agent write is rejected and terminal command/output is unavailable while metadata reads remain.

## User-only lifecycle and Git history

1. Return to `autonomous + allow`, reconfigure and restart Codex.
2. Save the ordinary experiment candidate and use the native user command to Finalize. Confirm automatic checkpoints made no Git commits.
3. Use normal Git squash/rebase manually and verify the intended formal commit history.
4. In a separate clean repository, run **Start Managed Worktree Experiment (Advanced)**, create two private user commits, accept one and promote it from the original target window. Confirm exactly one target commit is added, its tree equals the accepted commit, and nothing is pushed or automatically deleted.

## Report

Produce `vscode-agent-bridge-0.6.0-acceptance.md` and matching JSON with:

- Windows architecture/version, Git version, VS Code version and extension version;
- VSIX and installed MCP executable SHA-256;
- one pass/fail item for direct `0.5.1` upgrade, stale-config Doctor detection, protocol v5 and the 26-tool surface;
- one pass/fail item for zero-change decline, `.vscode` creation, JSONC preservation, inventory-only launch/tasks/workspace handling, explicit disable and read-only enforcement;
- one pass/fail item for Agent naming, list, rename, stale-title refusal, explicit checkpoint, prohibited lifecycle tools, each visibility policy and Activity privacy/reset;
- one pass/fail item for unsaved read, atomic stale rejection, formatter apply/no-op, pure-text Code Action, unsafe-action rejection, guarded save and terminal read-only observation;
- one pass/fail item for zero automatic ordinary-workflow commits and Managed accepted-tree identity;
- `automaticGitCommitsCreated: 0`, `terminalWriteToolsExposed: 0`, `managedTargetCommitsAddedByFinalize: 1`, and `overallStatus: "passed" | "failed"`.

Replace home, repository and managed-worktree prefixes with `<HOME>`, `<REPOSITORY>` and `<MANAGED_WORKTREE>`. Do not include usernames, email addresses, tokens, IPC endpoints, raw Codex configuration, terminal command/output, source, absolute paths or unrelated files. A failed item keeps the candidate unpublished and should produce a later patch rather than rewriting `0.6.0`.
