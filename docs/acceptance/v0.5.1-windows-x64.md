# VS Code Agent Bridge 0.5.1 Windows x64 acceptance

Use this procedure on a different Windows x64 computer with a clean VS Code profile, Git, no Bun or Node.js, and no clone of this repository. `0.5.1` is an unpublished side-load patch candidate.

## Install and configure

1. Verify the test-bundle archive against its `.sha256` file, then verify the extracted files against `SHA256SUMS.txt`.
2. Install `vscode-agent-bridge-0.5.1-win32-x64.vsix` using **Extensions > ... > Install from VSIX...**.
3. Confirm the extension ID is `AliceLin.vscode-agent-bridge` and version is `0.5.1`.
4. Run **Configure Agent Policies**, select `autonomous + allow`, then run **Configure Codex**, confirm and restart Codex.
5. Run **Run Doctor**. It must report protocol v4, aligned versions, current policy/config, a live bridge and healthy storage. It must not print source, command lines, terminal output, tokens, IPC endpoints, usernames or absolute paths.

## Ordinary experiment branch (default)

Create an unrelated disposable local Git repository with a named experiment branch, two existing TypeScript files and a `tsconfig.json`. Also create an existing `action.bridgeaction` text file containing `BROKEN_E2E`. Make an initial commit and open the repository in VS Code.

Temporarily enable the machine setting `vscodeAgentBridge.enableAcceptanceFixtures`. This opt-in fixture is disabled by default and provides one deterministic pure-text Quick Fix named **Apply VS Code Agent Bridge acceptance text edit** for the `.bridgeaction` file. Disable the setting after this section.

1. Run **Start Agent Experiment**.
2. Ask Codex to discover the exact VS Code instance and read an unsaved unique editor marker that is absent from disk.
3. Ask it to make several guarded edits through Change Sets and use the VS Code formatter twice on an already formatted document. The second call must succeed with `applied: false`, `editCount: 0`, `checkpointId: null`, and unchanged version/hash.
4. Ask it to list Quick Fixes for `action.bridgeaction` and apply **Apply VS Code Agent Bridge acceptance text edit**. Confirm the buffer contains `FIXED_E2E`, remains dirty before an explicit save, and produces an Agent Apply checkpoint.
5. Confirm command-only or resource-operation Code Actions are reported inapplicable and cannot execute.
6. Ask Codex to save an existing changed document. Confirm the final buffer/disk hash reflects format-on-save and a `save` checkpoint exists.
7. Try an outdated version/hash and an `untitled:` document. Confirm the entire operation is rejected without partial modification or file creation.
8. Without accepting a checkpoint, save all captured documents and run **Finalize Agent Experiment**. Autonomous Finalize should create a final explicit checkpoint and end the session without staging or committing.
9. Repeat after explicitly accepting a candidate, then change the current content. Finalize must reject until **Restore Accepted Candidate** is used and the restored content is saved.
10. Confirm the automatic checkpoint timeline added no Git commits. Use normal Git interactive rebase/squash manually and verify the chosen formal history.
11. Disable `vscodeAgentBridge.enableAcceptanceFixtures`.

## Terminal observation

1. Open two VS Code terminals: one with Shell Integration and one without if feasible.
2. In the integrated terminal, manually start a command that prints a unique start marker, waits at least five seconds, prints a completion marker and exits successfully.
3. While it runs, ask Codex to list terminals and executions. Confirm `running`, start time, command confidence and explicit coverage are returned.
4. Ask Codex to read output in small pages. Confirm both markers can be reconstructed, the cursor advances, ANSI/control sequences are absent and the final exit code/status are correct.
5. Confirm pre-activation commands, a no-integration terminal or any missing prefix is reported as unavailable/partial rather than complete.
6. Close the terminal and confirm its metadata remains briefly available. Restart VS Code and confirm prior captured executions are not restored.
7. Ask Codex to create a terminal, send input or execute a command. Confirm no such MCP tool exists.

Do not run secrets during this test. Terminal observation is read-only but captured output can still contain sensitive text.

## Policy transitions

After every policy change, rerun **Configure Codex** and restart Codex before checking its advertised tool list. The extension-side refusal should take effect immediately even before reconfiguration.

1. Select `review + allow`. Confirm Codex prompts for write tools and Finalize rejects a session without an explicitly accepted checkpoint.
2. Select `readOnly + metadataOnly`. Confirm editor/language/experiment reads and terminal metadata remain available; every Agent write, execution-list and output-read request returns `POLICY_DENIED`.
3. Select terminal policy `deny`. Confirm no terminal tool is enabled after reconfiguration and direct stale-client terminal calls are rejected.
4. Return to `autonomous + allow`, reconfigure and restart. Doctor must report the config as current.

## Managed Worktree advanced smoke test

From a separate clean disposable repository, run **Start Managed Worktree Experiment (Advanced)**. Confirm the private worktree opens and remains isolated, create two user-controlled private commits, accept one and promote it from the original clean target window. Verify Finalize adds exactly one target commit whose tree matches the accepted commit and does not push or automatically delete the worktree/branch.

## Report

Produce `vscode-agent-bridge-0.5.1-acceptance.md` and matching JSON containing:

- Windows architecture/version, Git version, VS Code version and extension version;
- VSIX and installed MCP executable SHA-256;
- one pass/fail item for installation, Doctor privacy, 21-tool surface, unsaved read, guarded edits, format, repeated-format no-op, format-on-save, opt-in pure-text Code Action, unsupported action rejection, guarded save, autonomous Finalize, accepted-candidate precedence and zero automatic Git commits;
- one pass/fail item for live terminal state, paged output, exit code, coverage gaps, restart loss, no terminal-write tool, review prompts, read-only enforcement, metadata-only redaction and deny enforcement;
- one pass/fail item for the Managed Worktree advanced smoke test and accepted-tree identity;
- `automaticGitCommitsCreated: 0` for the ordinary workflow;
- `terminalWriteToolsExposed: 0`;
- `managedTargetCommitsAddedByFinalize: 1`;
- `overallStatus: "passed" | "failed"`.

Replace home, repository and managed-worktree prefixes with `<HOME>`, `<REPOSITORY>` and `<MANAGED_WORKTREE>`. Do not include usernames, email addresses, tokens, IPC endpoints, full Codex configuration, raw command lines/output, absolute paths or unrelated source. A failed item keeps the candidate unpublished and should result in a later patch candidate.
