# VS Code Agent Bridge 0.3.0 Windows x64 acceptance

Use this procedure on a different Windows x64 computer with a clean VS Code profile, no Bun or Node.js, and no clone of this repository. `0.3.0` is an unpublished side-load candidate.

## Install and configure

1. Verify `SHA256SUMS.txt` and the test-bundle archive hash.
2. Install `vscode-agent-bridge-0.3.0-win32-x64.vsix` using **Extensions > ... > Install from VSIX...**.
3. Confirm the extension ID is `AliceLin.vscode-agent-bridge` and version is `0.3.0`.
4. Run **VS Code Agent Bridge: Configure Codex**, confirm the operation, restart Codex, and run **Run Doctor**.
5. Doctor must report protocol v3, aligned versions, a live bridge, current config and healthy experiment storage without printing a username, source text, token, IPC endpoint or absolute path.

## Experiment scenario

Create a new ordinary local Git repository containing two small TypeScript files and one `tsconfig.json`, make an initial commit, and confirm the worktree is clean. Record the initial HEAD.

1. Open one tracked file, add a unique marker without saving, then run **Start Agent Experiment**. Record the displayed session ID.
2. In a new Codex task, call `vscode_list_instances`, read the unsaved marker, and call `vscode_get_experiment` with the selected instance.
3. Ask Codex to prepare and apply at least three different text Change Sets. After each apply, confirm the buffers are dirty and the disk files have not changed until you save manually.
4. Prepare a two-document Change Set, manually change one target before apply, then apply it. It must return `STALE_CHANGE_SET` and neither prepared edit may be partially applied.
5. Exercise `vscode_prepare_rename` on a TypeScript symbol and apply it. Confirm definition/references still resolve and no file was created, deleted or renamed.
6. Record one test result through `vscode_record_experiment_evidence`. It must appear as `client-reported`, not extension-verified.
7. Make a manual edit, wait for capture, save a document, and create an explicit checkpoint. Confirm distinct sources appear in the Experiments view.
8. Restart VS Code. The active session, timeline, accepted state and snapshots must still be available without restarting the repository from scratch.
9. Review a snapshot diff, select a checkpoint as accepted, make another temporary edit, then run **Restore Accepted Candidate**. A safety checkpoint must be added; restored buffers must remain dirty and disk content must not change until saved.
10. Save all restored documents and run **Finalize Agent Experiment**. Confirm the session becomes finalized and the Git HEAD still equals the initial HEAD. The extension must not stage or commit anything.
11. Pin/unpin the session, inspect Doctor storage counts, and delete only the finalized experiment data after confirming the warning.

Also verify that a resource create/delete during a separate disposable session adds an incomplete-coverage warning and causes whole-session restore to refuse rather than silently losing the resource change.

## Report

Produce `vscode-agent-bridge-0.3.0-acceptance.md` and matching JSON with:

- Windows architecture/version, VS Code version and extension version;
- VSIX and installed MCP executable SHA-256;
- one pass/fail item for installation, Doctor, all fourteen tools, persistence, stale atomicity, dirty-buffer behavior, evidence labelling, restore, Finalize and unchanged Git HEAD;
- `overallStatus: "passed" | "failed"`.

Replace home and project prefixes with `<HOME>` and `<WORKSPACE>`. Do not include usernames, tokens, IPC endpoints, full Codex configuration, raw absolute paths or unrelated source content. A failed item keeps this candidate unpublished and should result in a patch candidate.
