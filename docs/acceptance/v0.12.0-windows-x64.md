# VS Code Agent Bridge 0.12.0 Windows x64 acceptance

Run this procedure on a different Windows x64 computer or under a separate restricted local user with a clean VS Code Profile, no Bun or Node.js and no clone of this repository. Install the checksum-verified VSIX directly over `0.11.0`; do not uninstall first. Use a disposable trusted TypeScript workspace and never include descriptor tokens, IPC endpoints, source, terminal output or raw Codex configuration in the report.

## Upgrade, lifecycle and identity boundary

1. Confirm extension ID `AliceLin.vscode-agent-bridge`, version `0.12.0`, protocol v11 and exactly 64 tools after rerunning **Configure Codex** and restarting Codex.
2. During a reload with non-trivial existing experiment data, confirm the instance is discoverable as `initializing` before becoming `ready`. A deliberately corrupt disposable journal must become `degraded`; Doctor must not report overall health.
3. Confirm Doctor reports separate installation, runtime and workspace-data health plus lifecycle, registry ACL, corrupt/recovery, managed attention and Profile journal attention.
4. From the second restricted user, confirm the descriptor cannot be read and its token cannot be obtained. Confirm an unauthenticated named-pipe request fails. Do not copy the descriptor or weaken its ACL to perform this check.
5. Place a sanitized old-protocol descriptor envelope in an isolated registry fixture. Confirm it is listed as `incompatible`, is not deleted merely for being old, and explicit selection returns `PROTOCOL_MISMATCH`.

## Observable autonomous Task and Debug workflows

1. Start an ordinary experiment and prepare each Task form: Shell command line, structured Shell command/args and Process/args. Confirm the preview shows full command, args and root-relative cwd, but only environment keys.
2. Run a prepared Task that creates a disposable file, writes a unique terminal marker, accesses a harmless network endpoint or starts a disposable external process. Confirm the VS Code Task terminal is revealed, Activity links prepare/start/execution/terminal/exit/checkpoint and the terminal API can read the marker.
3. Change command, args, cwd and environment independently and confirm each changes the definition fingerprint. Confirm `runOn`, `dependsOn`, a root-external cwd, expired IDs and the wrong session/root are rejected.
4. Persist a prepared Task with the exact `tasks.json` existence/hash precondition, enumerate it as `agentPersisted` and run it again. Confirm a same-name user Task is never overwritten and stale file hashes fail.
5. Prepare and start one JSON-compatible adapter configuration. Confirm type/request/program/runtimeExecutable/args/cwd and environment keys are visible, environment values are absent, Debug output is captured and termination creates a checkpoint.
6. Bind pre/post Tasks by task ID plus fingerprint and confirm Task drift prevents Debug start. Persist the configuration with the exact `launch.json` hash and confirm a same-name user configuration is not overwritten.
7. Confirm external services, databases, network effects, processes, environment changes and Git history are reported as unrecoverable even when workspace text/resources have a checkpoint.

## Paths, language grants and configuration recovery

1. In disposable fixtures, confirm file/directory symlinks and Windows junction/reparse paths cannot escape a trusted root, including a missing target below a reparse ancestor. Replacing a validated path before apply must be rejected on revalidation.
2. Confirm open documents and canonical file URIs inside a trusted root are readable. An arbitrary external file or virtual URI must be denied.
3. Resolve a definition/reference into an external library URI, read that exact URI with its returned grant, and confirm a sibling URI, different instance and expired grant are denied. A granted provider result may create a next-hop grant only for its exact returned URI.
4. Confirm extension configuration get returns defined state, SHA-256, type, scope and risk classification without raw effective/target values. Credential-like keys must be denied.
5. Exercise Global Profile update failure and startup recovery in a disposable Profile. Confirm pending is written before update, a failed update rolls back, after-hash recovery commits, before-hash recovery removes pending and ambiguous state requires Doctor attention.
6. Leave a legacy `aggressive` setting and an existing folder-open Task. Confirm execution safely remains explicit, Doctor offers to open the settings/configuration and neither value is automatically deleted.

## Runtime bounds and report

1. Confirm default Output inventory omits `extensionCapability` entries and prioritizes readable, active and recent sources. An explicit `sourceTypes: ["extensionCapability"]` query must still return the metadata inventory.
2. Generate enough privacy-safe tool calls to observe Usage Insight rotation at 1 MiB. Confirm recurring prune, a total size no greater than 20 MiB and shutdown flush without parameters, results, paths, environment values or terminal/Debug content.
3. Recheck experiments, formatter no-op, pure-text Code Action, resource recovery, Marketplace/Profile orchestration, reviewed Python adapter and Managed Worktree promotion.
4. Produce privacy-scrubbed Markdown and JSON reports with Windows/VS Code/extension/protocol versions, supplied artifact SHA-256 values and per-step pass/fail/untested state.

Only `overallStatus: passed` marks `0.12.0` as Windows x64 cross-user/cross-machine verified. A failure keeps this candidate immutable and should produce a patch release.
