# v0.11.0 extension integrations release audit

- Date: 2026-08-10
- Status: `completed_with_findings`
- Scope: protocol v10, 60 tools, static reviewed adapters, official Python environment facade and release candidate gates
- Environment: Windows x64; Bun 1.3.11; isolated VS Code 1.132.0 Extension Host

## Method and preconditions

The audit uses protocol/unit tests, source-boundary scans, MCP STDIO registration, a real two-window Extension Host run and packaged-artifact gates. The isolated automated Profile intentionally does not install `ms-python.python`, so it validates non-activation and the explicit missing-extension state. Real Publisher Trust, Python installation and active-interpreter resolution remain part of cross-machine acceptance.

## Findings

1. Severity: low, not a product failure. The first VS Code 1.132.0 test-host launch exited before executing a test and emitted no business stack. An immediate clean rerun completed both Extension Host suites in 60 seconds. The final gate must rely on the passing complete run and retain this transient host evidence rather than treating the empty first run as product validation.
2. Severity: informational, open validation boundary. Automated tests do not install Marketplace extensions. The positive facade activation and resolved-interpreter path therefore remains explicitly unverified until the cross-machine v0.11 procedure runs.

## Side effects and artifacts

Tests created only temporary repositories, Extension Host Profiles, experiments and managed worktrees. E2E restored workspace and settings state. No extension was installed, no remote operation ran and no user `.idea`, `.codex` or workspace settings were committed.
