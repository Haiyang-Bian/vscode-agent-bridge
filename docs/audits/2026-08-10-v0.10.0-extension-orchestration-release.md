# v0.10.0 extension orchestration release audit

- Date: 2026-08-10
- Status: `completed_with_findings`
- Scope: protocol v9, 58 tools, Marketplace query/plans, native installation boundary, current-Profile configuration and release candidate gates
- Environment: Windows x64; Bun 1.3.11; isolated VS Code 1.132.0 Extension Host

## Method and preconditions

The audit used contract/unit tests, source-boundary scans, a real two-window Extension Host run and packaged-artifact gates. Marketplace network behavior was tested with bounded fake Gallery responses; real public Gallery/Publisher Trust completion remains part of cross-machine acceptance.

## Findings

1. Severity: high, resolved. Importing the package root of `jsonc-parser` added a UMD dynamic `require('./impl/format')` to Bun's extension bundle, causing activation failure. The import now targets the package's ESM entry explicitly, and the bundle plus real Extension Host pass.
2. Severity: medium, resolved. Rejecting a non-`file:` `globalStorageUri` at activation was stricter than the existing Experiment storage contract and failed the isolated host. The Profile journal now uses the same local `fsPath` convention; remote windows still do not publish the Bridge.
3. Severity: medium, resolved. `https-proxy-agent` also made the extension bundle dependent on package-internal runtime files. It was removed in favor of a fixed-host, bounded Node `net`/`tls` CONNECT tunnel; no runtime dependency or generic proxy request surface remains.

## Side effects and artifacts

Tests created only temporary repositories, Extension Host profiles, experiment data and Profile journal entries under temporary/global test storage. E2E restored the tested Global setting and cleaned workspace files. No Marketplace extension was installed during automated tests, no remote operation ran and no user `.idea`, `.codex` or workspace settings were committed.

## Closure criteria

Local closure requires the full Bun check, real Extension Host, EXE, VSIX, test bundle, packaged smoke, audit and checksums. Cross-machine closure additionally requires the public Marketplace, Publisher Trust, reload and active-Profile procedure in `docs/acceptance/v0.10.0-windows-x64.md`.
