## Findings

### 1. E2E marker retained the v0.8 tool-count literal

- Severity: low
- Evidence: the first v0.9 Host run completed both tests, but the outer wrapper rejected a marker containing the hard-coded count `44` while the authoritative catalog contained 53 tools.
- Impact: false-negative release gate; no Bridge runtime failure.
- Resolution: the marker now derives its tool count from `MCP_TOOL_NAMES`. The complete source E2E passed afterward.

### 2. VS Code exposes incomplete Output/Profile coverage through stable APIs

- Severity: informational
- Evidence: stable APIs expose open Output documents and installed extensions but do not enumerate every Output Channel or reveal the active Profile name/ID.
- Impact: the Bridge cannot honestly claim complete channel history or Profile identity.
- Resolution: results carry explicit coverage, unavailable Profile fields are `null`, and reading never invokes private storage or channel-switch commands.
