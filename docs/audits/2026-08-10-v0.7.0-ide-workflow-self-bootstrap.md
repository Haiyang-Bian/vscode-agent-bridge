## Scope and method

This independent run tests the v0.7 IDE workflow expansion and rechecks the two earlier self-bootstrap defects: cancellation escaping the MCP boundary and slow recovery of a large experiment journal. It combines an installed-extension observation in the real self-hosting workspace, focused contract and regression tests, the full repository gate, and an isolated Windows Extension Host E2E run.

Live probes were deliberately bounded. Read-only inventory and status calls were allowed against the real workspace. A legacy resource-history preparation was used to exercise a compatibility rejection without applying a change. A Task request that could have external side effects was stopped by the MCP client's risk approval layer; the rejection was not bypassed. Valid Task and Debug execution were exercised only in the disposable E2E workspace.

This report records metadata and aggregate evidence only. It excludes raw configuration, task commands, terminal output, debug expressions and values, DAP traffic, IPC endpoints, source snapshots, machine-specific roots and instance or session identifiers.

## Findings and closure state

### AUDIT-2026-08-10-01: installed large-journal closure passed

- Original severity: High
- Status: Closed for this host and release candidate

The installed v0.7 extension registered a usable `ready` instance over the preserved 132,624,227-byte legacy journal in 3.417 seconds. This supplies the real-workspace validation that remained open in the v0.6.1 report. It is one bounded observation rather than a cold-start performance benchmark, but it is comfortably below the former failure boundary and required no journal deletion or rewrite.

### AUDIT-2026-08-10-02: cancellation closure remains passed

- Original severity: High
- Status: Closed

The current v0.7 E2E run still closes the client connection while onboarding confirmation is pending, observes request rejection, waits for the delayed path and verifies that onboarding remains unconfigured. The two lower-level regressions also verify that timeout and caller cancellation destroy the bridge socket. The workflow therefore remains protected at both RPC and real Extension Host layers after the v0.7 expansion.

### New blocking defects

None found in the exercised scope.

The client-side Task rejection is expected policy behavior, not a bridge defect. It also means this run does not claim that a valid Task or Debug target was launched in the user's real workspace. Those side-effecting paths are covered by the isolated E2E run instead.

VS Code emitted non-fatal host and deprecation warnings during E2E startup. They did not fail activation, the bridge workflows or host shutdown, and this run found no evidence tying them to the extension's functional behavior.

## Side effects and artifacts

- Repository builds produced their normal ignored outputs, but the installed experiment did not add a checkpoint or increase storage.
- The E2E runner created an isolated temporary Git workspace, started two Extension Host processes and observed both exit successfully.
- The legacy resource probe stopped at `EXPERIMENT_UPGRADE_REQUIRED`; it created no file and applied no change set.
- No Task or Debug session ran in the real self-hosting workspace, and no workspace setting was changed by the live probes.
- Pre-existing unrelated `.idea`, `.codex` and workspace-settings changes were preserved unchanged.
- This run creates only this audit report and its directory index entry. No Git commit is created.

## Closure criteria and next gate

Both previously reported self-bootstrap issues are closed for the installed v0.7 candidate on this host. The v0.7 workflow scope is complete for local automated and isolated Extension Host validation.

Release-wide closure still requires the documented Windows x64 acceptance procedure on a second machine or clean user profile, using checksum-verified packaged artifacts. That run should confirm installation, migration, master-switch recovery, JSONC/resource recovery, and one explicitly approved Task and Debug workflow without relying on this machine's existing extension state.
